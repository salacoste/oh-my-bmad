## Epic Summary

Epic 1 was the foundation: **monorepo proof → service/MCP scaffolds → upstream vendoring → compose + .env + justfile → test tree + CI skeleton → architectural CI gates → secret hygiene → Dockerfile.base + multi-stage builds → GHCR image publishing → operator documentation set**. Eleven stories, 19 commits in the canonical scaffold-then-review-fix rhythm, closed on 2026-04-24. Tests grew 0 → 75 (Story 1.7 alone added 75; the other ten were pure infrastructure).

The epic delivered every architectural CI gate (`check_imports`, `check_event_registry`, `check_single_writer`, `check_no_subprocess` came in 3.8) on which Epics 2 and 3 depend. It delivered the deployment surface (`docker compose up` brings a healthy stack up). It delivered both Bootstrap and MVP-ship operator docs.

The retrospective deferral was the central operational mistake. Five weeks of dev-loop friction (`uv sync --no-dev` recovery, schema-registry teardown re-discovery, per-test-tree mypy-strict re-discovery, MCP-naming-exception re-lookup) accumulated across Epic 2 and Epic 3 while this document waited. Epic 2's retrospective surfaced the implicit Epic 1 lessons under "Lessons Applied (from prior implicit learnings — Epic 1 retro never run)" and raised an Action Item to run this retro before Epic 3 kickoff. That Action Item slipped, then was nudged twice more during Epic 3 status checks. This document is the resolution.

## Story-by-Story Narrative

The first story. Established the `uv` workspace shape (`uv.lock` at root, `[tool.uv.sources]` with workspace declarations), the seven service/package/MCP directories, and the smoke-import test that verifies every workspace member resolves under `uv sync`. Two commits (scaffold + single-pass review fixes). The decision to use `uv` (not Poetry, not pip-tools) survived two epics without revision — most consequential first-story decision in the project.

### 1.2 — Remaining services + MCPs + packages (`5df4197` → `22f8da0`)
Filled in the directory shapes Story 1.1 stubbed. `services/{registry-api,registry-state,clawhip-daemon,worker-wrapper,telegram-gateway}`, `mcp-servers/{clawhip-bridge,task-registry,session-registry}`, `packages/{events,secret-hygiene,idempotency}`. Each directory got a `pyproject.toml` workspace member with the canonical `[tool.uv.sources]` + `[tool.ruff]` + `[tool.mypy]` shape. Two commits.

### 1.3 — Upstream vendoring + migrator scaffold (`d2ae9d3` → `da2fc39`)
The vendored upstream code lives in `vendor/` with `VENDORED.md` capturing the upstream SHAs at sync time. The infrastructure-as-code surface: `docker-compose.yml` with 6 services + healthchecks; `.env.example` with every variable the stack reads; `justfile` with `bootstrap-verify`, `up`, `down`, `lint`, `test`, `bootstrap-image`. ### 1.5 — Test tree + CI skeleton (`6d03c0b` → `0ea617e`)
The test discipline forge. Established co-located tests under `<package>/src/<package>/test_*.py`, the `tests/` top-level tree for cross-cutting integration tests, the GitHub Actions CI matrix, the `mypy --strict` invocation pattern, and `ruff check . && ruff format --check .` as the lint gate. ### 1.6 — CI gates: imports + event registry + single-writer (`fbf18d7` → `a834f11`)
The architectural CI gates: `scripts/check_imports.py` (forbidden cross-service imports), `scripts/check_event_registry.py` (every event type registered in exactly one service-side registration site), `scripts/check_single_writer.py` (only registry-state writes to its SQLite). The `noqa: IMP001` / `EVT001` / `SW001` tag system in this story is the same one referenced 60+ times across Epic 2 + Epic 3. Two commits.

### 1.7 — Secret-scanner pre-commit + log sanitizer (`9ca0674` → `1ab905a`)

The `.secret-hygiene-ignore` file with three test-fixture exceptions (realistic-shape secret tokens needed for testing). The sanitizer pattern was reused unchanged in Stories 2.16 + 2.17 + 3.7 + 3.8. Two commits.

### 1.8 — Dockerfile.base + multi-stage per-service builds (`a30df60` → `3886c12`)
Shared `Dockerfile.base` with stage-1 `uv sync --frozen --no-dev --all-packages` into `/opt/venv`, stage-2 `python:3.12-slim-bookworm` + `/opt/venv` + per-service entrypoint. ### 1.9 — GHCR image publishing (`3211e18` → `0b3511b`)

Tag-trigger workflow stays inert until the first tag (deferred — see Action Item 1). The 5 floating GitHub Actions tags (`actions/checkout@v4`, `astral-sh/setup-uv@v3`, etc.) flagged for digest-pinning in a future supply-chain story (R4 in the risk register). Two commits.

### 1.10a — Deployment quickstart docs (single commit, mid-day on 2026-04-24)

## What Went Well

- **The `uv` workspace shape (Story 1.1) was the right call.** Single `uv.lock`, `[tool.uv.sources]` workspace declarations, fast resolution. Survived two epics without revision. Every Epic 2 + Epic 3 package added cleanly via `uv add --workspace`.
- **Architectural CI gates as AST analyzers (Story 1.6) caught real defects.** `check_imports` flagged 11 cross-service imports across Epic 2 + 3 that would have shipped without it. `check_event_registry` caught the schema-registration race that made registration in `packages/events/.../schema_registry.py` (vs `event_types.py`) impossible — discovered by Story 3.9 H7.
- **`# noqa: <TAG>` per-rule suppression with mandatory inline reason (Story 1.6).** Every suppression is searchable; every suppression has documented intent. The pattern is now the project's universal architectural-exception mechanism.
- **Co-located tests under `<package>/src/<package>/test_*.py` (Story 1.5).** Test → source distance is one directory. Survived 28+ stories without anyone proposing a separate test tree at the package level.
- **Multi-stage `Dockerfile.base` + thin per-service overrides + non-root UIDs (Story 1.8).** Image floor at 151 MB (Python services), 286 MB (worker-wrapper with Node). Reproducible builds via `uv sync --frozen`. Architectural shape held through Epic 3.
- **`AuditedSecret` pattern (Story 1.7's secret hygiene foundation) was extended cleanly in Story 2.16 (`secret.accessed` audit event).** First-occurrence cost was paid in 1.7; second-occurrence in 2.16 was an extension, not a rework.
- **Two-commit cadence (scaffold → review-fix) stabilized at Story 1.3 and held without exception** through the entire scaffold epic. Stories 1.10a + 1.10b were the only single-commit stories — no review issues found.
- **Single-pass review thoroughness.** No round-2 review-fix commits in Epic 1. Stories 1.4 / 1.5 / 1.7 / 1.8 each closed in single fix-commit passes despite finding-counts that warranted round-2 in any other context.
- **`bootstrap-verify` as the validation contract (Story 1.4 + 1.10a).** Recipe runs the deployment quickstart end-to-end. Used as a pre-PR check across every Epic 2 + Epic 3 story.

## What Struggled

- **Pytest configuration was revisited multiple times.** Stories 1.5 + 1.6 both touched `pyproject.toml::tool.pytest.ini_options`. The `tests/` conftest discoverability question (later flagged in Story 2.4 as "not discoverable from `services/**`") was latent in 1.5; the convention to "inline fixtures locally" was never explicitly documented. Re-discovered in Stories 2.5 / 2.6 / 2.10 / 2.11 / 3.6 — six total re-discoveries before Epic 2's retro made it Action Item 10. This retro promotes it to first-occurrence status.
- **`uv sync --no-dev` strips dev deps the test suite needs.** First surfaced as a transient confusion in 1.5 (asgi-lifespan was missing for some lint runs); the workaround `uv sync --all-packages` was discovered ad-hoc and never documented. Re-discovered in Story 2.16, then 2.17, then explicitly in 3.6 / 3.7 / 3.8 / 3.9 / 3.10 / 3.11 — eight re-discoveries before Epic 2's retro raised it (Action Item 4) and this retro re-raises it (Action Item 2 below) as a 9th nudge.
- **Schema-registry teardown collision pattern was latent in 1.6 + 1.7.** The `_clean_registry` autouse-fixture pattern that Stories 2.13 / 2.16 / 2.17 needed was never named in Epic 1 because Epic 1 had only one story (1.7) using the schema registry, so collisions never surfaced. Re-discovered in Epic 2's first three multi-event stories.
- **MCP-naming exception (`clawhip-bridge` is hyphenated against the `_` MCP convention) was discovered late.** Story 1.2 introduced the hyphen-name; nobody flagged the convention drift until Story 2.8 (`clawhip-bridge` MCP server) needed the import path. The Epic 2 retro documents the resolution; Epic 1 retro flags the original miss.
- **GHCR tag-trigger workflow stays inert.** Story 1.9 ships the workflow but no tag has been pushed. The first tag will surface any latent issues; today there is zero validation that the workflow actually publishes correctly. R1 in the risk register.
- **5 floating GitHub Actions tags at Story 1.5 + 1.9.** `actions/checkout@v4`, `astral-sh/setup-uv@v3`, etc. Not digest-pinned. Supply-chain risk acknowledged but deferred to a future story.
- **Worker-wrapper image at 286 MB.** Floor is 272 MB (151 Python + 121 Node). Phase 1 budget; Phase 2+ may want to optimize.
- **`# SCAFFOLD VERSION` markers in transitional Dockerfiles (Story 1.4 → removed in 1.8).** A scaffolding pattern that was never formally tracked. Future-me search query (Appendix F) covers this.
- **Per-test-tree mypy-strict override convention was never written down.** Every new test tree under `tests/` needs a `[mypy-tests.<tree>.*] ignore_errors = False` entry in `mypy.ini` AND extension of the second mypy invocation in the `lint` recipe. Implicit in Stories 1.5 / 1.6 + four Epic 2 stories. Epic 2 retro Action Item 12; second nudge below.

## Recurring Patterns

- **Scaffold-before-content discipline.** 9 of 11 Epic 1 stories shipped pure infrastructure with zero new tests; only 1.7 (secret hygiene) shipped runtime logic + 75 tests. This is the literal definition of "infrastructure forge".
- **Two-commit story cadence:** scaffold + review-fix pass. Stabilized at Story 1.3; held through Epic 1 and was reused unchanged across both subsequent epics. Average 4 commits per Epic 2 story (the cadence absorbed a docs-finalize + mark-done third commit by then).
- **Architectural decisions encoded as CI gates rather than prose.** `check_imports` enforces the spine boundary; `check_event_registry` enforces the registration discipline; `check_single_writer` enforces the SQLite ownership; `check_no_subprocess` (later in 3.8) enforces the no-shell-out rule. Each gate is more durable than the architecture-doc paragraph that motivated it.
- **`# noqa: <TAG> — Story X.Y AC-Z` inline-reason suppression pattern.** Established in 1.6; reused 60+ times across Epics 2 + 3. Every suppression is grep-able to a justification.
- **Spec-as-source-of-truth, code-as-implementation.** Each story spec captured ACs and Dev Notes; the dev pass implemented; the review pass found defects against the spec; the review-fix commit closed them. Pattern stable.

## Cross-Cutting Architectural Discoveries

### `uv` workspace + single `uv.lock` is the right shape for service monorepos
Story 1.1's foundational decision. Faster than Poetry. The `[tool.uv.sources]` workspace declarations let every service depend on every package without publishing to a local index. Survived two epics. No serious alternative considered after first-week shake-out.

### AST-based architectural CI gates beat documentation
Story 1.6's gates are concrete: `forbidden_imports`, `event_registry_uniqueness`, `single_writer_per_table`. Each catches real defects in CI before they ship. The architecture doc lists them as constraints; the gates enforce them. The next architectural concept (no-subprocess for spine code) added a 4th gate in 3.8 — pattern repeats.

### Multi-stage Dockerfile.base + per-service overrides scale to 6 services without churn
Story 1.8. One base image, one stage-1 build (uv sync), 6 stage-2 entrypoints. Worker-wrapper composes Python + Node via multi-stage — the only deviation from the simple shape. Image-size floor known and documented. R3 in the risk register tracks the worker-wrapper growth ceiling.

### Co-located tests + co-located source = one-directory test → source distance
Story 1.5 + 1.6. Test files live next to the modules they test. `pytest --rootdir=.` discovers them. No separate test tree at the package level. Convention scaled to 28+ stories.

### `# noqa: <TAG> — <reason>` is the project's universal architectural-exception mechanism
Story 1.6. Every architectural exception is grep-able to a documented justification. The mechanism extended cleanly to new gate types (3.8 added `noqa: SUBP001`) and to non-architectural rules (`noqa: IMP001` for the cross-service-payload-import compromise). Single discipline; many use cases.

## Lessons That Did Apply to Epic 2 / Epic 3

These are the implicit Epic 1 lessons that Epic 2's retro had to capture under "Lessons Applied (from prior implicit learnings — Epic 1 retro never run)". Listing them explicitly closes the gap.

- **`uv` workspace shape held without revision.** Every Epic 2 / Epic 3 package added via `uv add --workspace`; no rework.
- **`# noqa: <TAG>` per-rule suppression** absorbed `EVT001`, `SW001`, `IMP001`, `SUBP001` extensions cleanly.
- **AST-based architectural CI gates** absorbed `check_no_subprocess.py` (Story 3.8) on the same template.
- **Co-located tests** held across all 28+ subsequent stories. No story needed a separate test tree.
- **Two-commit story cadence** (scaffold → review-fix) extended naturally to a 4-commit cadence in Epic 2 (added docs-finalize + mark-done) without breaking the underlying rhythm.
- **`AuditedSecret` foundation** extended cleanly into the `secret.accessed` audit event (Story 2.16). First-occurrence cost in 1.7; second-occurrence was an extension.
- **Migrator additive-version pattern** (Story 1.3 scaffold; Story 2.14 first real use; Story 3.10 / 3.11 follow-ons) absorbed every additive payload extension cleanly.
- **`bootstrap-verify` as the deployment-validation contract** caught regressions in 4 Epic 2 + 6 Epic 3 stories before they merged.

## Lessons That Did NOT Apply (and the cost of the 5-week deferral)

These are friction patterns that re-fired across Epic 2 and Epic 3 because Epic 1 retro never wrote them down.

- **`uv sync --no-dev` strips dev deps.** Re-discovered 8 times after Epic 1 (Stories 2.16, 2.17, 3.6, 3.7, 3.8, 3.9, 3.10, 3.11). Each re-discovery cost ~5-15 minutes of "why did mypy break?" diagnostic before someone remembered to run `uv sync --all-packages`. Total compounded cost: ~1 hour of friction. **If Epic 1 retro had documented the recipe, every Epic 2 + 3 story would have run it as habit.**
- **Schema-registry test-isolation pattern** (`_clean_registry` autouse fixture). Re-discovered in 2.13, 2.16, 2.17. Each re-discovery cost ~10 minutes diagnosing test-order pollution.
- **`tests/conftest.py` not discoverable from `services/**` co-located tests.** Re-discovered in 2.4, 2.5, 2.6, 2.10, 2.11. Each re-discovery cost ~5 minutes deciding whether to inline the fixture or fight pytest's fixture-discovery scope.
- **Per-test-tree mypy-strict override convention** (mypy.ini stanza + lint-recipe extension). Re-discovered in 4 Epic 2 stories adding new test trees.
- **MCP-naming exception** (hyphen vs underscore for `clawhip-bridge`). Re-discovered in Story 2.8 import-path debugging.

The 5-week deferral cost is real: ~1.5-2 hours of compounded re-discovery friction across 13 stories that an Epic 1 retro would have eliminated by writing the patterns into `tests/README.md` and `CONTRIBUTING.md`.

## One Observation Worth Flagging That Doesn't Fit a Standard Section

Epic 1 ran in 6 wall-clock days (2026-04-22 to 2026-04-24, with documentation finalization through 2026-04-24's evening commit). 11 stories × ~2 commits each = 20 commits, including review-fix passes. That cadence — **roughly one story per half-day, sustained across 6 days** — is not reproducible without infrastructure-first discipline (every story dropped into a working harness because every prior story landed it) AND without single-pass review thoroughness (Stories 1.4 / 1.5 / 1.7 / 1.8 each closed in single fix-commit passes despite finding-counts that warranted round-2 in any other context).

The tradeoff: speed bought aggressive scope-cuts (FR18b custom ruff rule deferred, GHCR remote validation deferred via tag-trigger inertness, retro deferred for 5 weeks) AND it bought one specific failure mode — **the "lessons-applied document" was never written, and the resulting compounded re-discovery cost across Epic 2 + 3 is the single largest documented inefficiency in the project's history**. Five separate friction patterns were each re-discovered 3-8 times. Total compounded cost: ~1.5-2 hours of dev-loop friction across 13 stories.

This is not a regret about Epic 1's pace — Epic 1's speed was the right call given the operator-day budget and the infrastructure-first nature of the work — but it is a documented tradeoff. Future epics should not assume the same cadence is reproducible without the same discipline. And future epics should run their retrospectives at close, not weeks later. Action Item 6 is the policy fix.
