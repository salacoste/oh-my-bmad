2. **Surgical payload refactor** — 20 files changed, zero regressions. The decomposition pattern (pure models → shared package, registration → service, re-export shim → old location) is reusable.

3. **Test count stability** — 1158→1161 across 6 stories. Tech-debt work didn't destabilize the suite.

4. **Documentation as infrastructure** — development.md, ADR-0001, RENDERER_CONVENTIONS.md prevent re-discovery of the same issues in Epics 4-7.

5. **Phantom backlog items identified** — 3.5.6 discovered the regex fix was already applied (Story 3.8). Untracked fix created a phantom debt item.

## Challenges

1. **Hypothesis accuracy** — Story 3.5.4's pre-investigation hypothesis (Docker Desktop macOS healthcheck timing) was completely wrong. Actual root cause: empty schema registry from a missing import. Time was spent chasing Docker before finding the real issue.

2. **"No production code changes" is aspirational** — Stories 3.5.2 and 3.5.4 touched production-adjacent code despite explicit declarations. The `envelope.py` Pydantic serializer fix and events package version bump were justified, but show tech-debt stories should plan for incidental production fixes.

3. **Code review finding volume** — Stories 3.5.5 and 3.5.6 had 13 combined review findings (2 HIGH, 6 MEDIUM, 5 LOW). All were real issues caught by the three-layer review system, but the volume suggests tighter self-review before marking stories for review.

---

## Key Insights

1. **Investigation-first beats hypothesis-first.** Don't codify assumptions in story specs before root-cause analysis.
2. **Tech-debt stories should allow incidental production fixes.** The "no production code" declaration creates false constraints when latent bugs are discovered.
3. **Untracked fixes create phantom backlog items.** Code-review fixes should be tracked immediately, not discovered in retrospectives.
4. **The circular-import decomposition pattern is reusable.** Applies to any future cross-service model refactoring.

---

## Action Items

### Process Improvements

1. **Time-box investigation before writing story specs.** When a story involves root-cause analysis, limit investigation scope before codifying hypotheses.
   - Source: 3.5.4
   - Applies to: future investigation-heavy stories

2. **Tech-debt story template: allow incidental production fixes.** Remove the false "no production code" constraint.
   - Source: 3.5.2, 3.5.4
   - Applies to: future tech-debt sweep epics

3. **Track code-review fixes as they happen.** Don't defer tracking to retrospectives.
   - Source: 3.5.6
   - Applies to: all code-review workflows

### Team Agreements

- Self-review more thoroughly before marking stories for review (reduce review finding volume)
- Circular-import decomposition pattern (3.5.2) is the canonical approach for cross-service refactors
- ADR format (3.5.5) for any architectural decision re-litigated in 2+ code reviews
