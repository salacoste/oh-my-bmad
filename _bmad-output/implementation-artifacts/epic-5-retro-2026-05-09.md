## Successes

1. **Event-level deduplication breakthrough (5.17c)** — Upgrading from task-level to event-level dedupe with composite keys (`task.step.completed.N`) was the key enabler for S-2 mid-flight worker swap. This was identified mid-review as a CRITICAL bug (plain `evt["type"]` key silently skipped multi-step events).

2. **TOCTOU-free worktree locking (5.3)** — The `O_CREAT | O_EXCL` kernel-enforced atomic lock acquisition eliminates the race window entirely. Review caught the original TOCTOU race and fixed it with an OS-level primitive.

3. **Callback-based LifecycleManager (5.17b)** — Dependency injection via callbacks (rather than direct MCP/GitHub imports) made the LifecycleManager fully testable without mocks — 8 integration tests covering restart scenarios.

4. **Independent GitHub adapter per service (5.14)** — The cross-service import prohibition forced each service to have its own GitHub adapter, maintaining independent deployability. PR creation failure is non-blocking — task completion still emits.

5. **Separate Docker compose overlays per test type (5.16, 5.17c, 5.18)** — S-1, S-2, and J-1 each have independent compose files, avoiding interference. The pattern of SHA-tagged idempotent builders was reused across all three.

6. **Structlog wiring consistency** — Third service to use the same structlog pattern (after registry-state, console-cli). Function-level loggers, no module-level structlog calls.

7. **Structured JSON deserialization is NOT stdout parsing (5.4)** — Critical architectural clarification: Claude Code's `--output-format stream-json` is structured deserialization, not the NFR-O1-banned `subprocess.check_output().decode()` pattern.

8. **S-1/S-2/J-1 test infrastructure** — Three tiers of Docker-based integration testing: cold swap (S-1), mid-flight swap (S-2), and full Journey 1 (J-1). Each proves a different aspect of the separability guarantee.

## Challenges

1. **110+ review findings across 20 stories** — While all resolved, the volume suggests initial implementation quality could be higher. Stories 5.1 and 5.2 each had 15 findings. The three-layer review (Blind Hunter + Edge Case Hunter + Acceptance Auditor) caught real bugs but at high cost.

2. **Async/subprocess lifecycle management (5.1, 5.3, 5.4, 5.10)** — CancelledError not caught (BaseException vs Exception), stderr deadlock from unidirectional pipe consumption, process leak on cancellation, sync code blocking event loop. Four different stories hit subprocess lifecycle issues.

3. **structlog `event=` keyword clash (5.17b, 5.18)** — `logger.info("msg", event=...)` silently clashes with structlog's positional `event` parameter. Discovered in 5.17b and explicitly warned in 5.18, but the tooling doesn't catch it.

4. **Pre-existing check_imports violation tolerated across 7 stories** — Story 5.5 introduced a violation in `test_reasoning.py` that was noted but not fixed by stories 5.6, 5.15, 5.16, 5.17a, 5.17c, and 5.18. "Not my scope" tolerance accumulated debt.

5. **Bounded-write stubs and NO-OP placeholders (5.8, 5.9)** — `_check_tier()` is a no-op, bounded-write tools are stubs. These are intentional Phase 1 design but create a "works but doesn't actually enforce anything" state that must be carefully tracked for Epic 6.

6. **Token extraction from OMC stdout via regex (5.13, 5.15)** — OMC is a Node CLI wrapping Claude Code; structured token counts aren't available. Regex parsing of unstructured output is fragile.

7. **Deduplication bugs found in adversarial review (5.17c)** — The event-level dedupe upgrade in 5.17c had a CRITICAL bug where plain `evt["type"]` keys caused multi-step events to be silently skipped. Also: detached sets from `.get()` not stored back in dict. Both caught in code review.

## Key Insights

1. **OS-level atomic primitives > application-level locking.** The `O_CREAT | O_EXCL` pattern (5.3) and `os.replace` (5.17b sidecar) both leverage kernel guarantees. When the review catches a TOCTOU race, the answer should be an OS primitive, not more application logic.

2. **Event-level deduplication is the right granularity for worker lifecycle.** Task-level dedupe was too coarse for mid-flight restart scenarios. The composite key pattern (`type + step_number`) enables fine-grained idempotency without losing event identity.

3. **Callback-based dependency injection enables testable infrastructure code.** The LifecycleManager (5.17b) uses callbacks for MCP emission and GitHub operations, making it testable without mocking transport layers. This pattern should be reused for future stateful components.

4. **Pre-existing violations compound faster than expected.** Story 5.5's check_imports violation was cited by 7 subsequent stories. Each "not my scope" decision adds friction and normalizes the debt. Fix violations immediately, even if unrelated to the current story.

5. **Subprocess supervision has predictable failure modes.** stderr deadlock, CancelledError process leaks, and sync blocking of event loop appeared across 4 stories. A subprocess supervision checklist or shared utility would reduce recurrence.

6. **Separate compose overlays per test type is the right pattern.** S-1, S-2, and J-1 each have isolated compose files. This avoids the "which test owns the shared compose?" problem and enables parallel test development.

7. **Story ordering matters for architectural coherence.** Implementing 5.8/5.9 (MCP servers) before 5.1 (worker scaffold) meant the worker had real servers to connect to during development, not just mocks.

## Action Items

### Process Improvements

1. **Fix check_imports violations immediately.** When a story introduces or encounters a check_imports violation, fix it in the same story — do not defer as "pre-existing" or "not my scope."
   - Source: 5.5 (introduced), 5.6/5.15/5.16/5.17a/5.17c/5.18 (tolerated)
   - Applies to: all future stories

2. **Add subprocess supervision checklist.** Before implementing subprocess management, verify: (a) stderr is drained concurrently, (b) CancelledError inherits BaseException, (c) process reference cleared after shutdown, (d) sync I/O wrapped in asyncio.to_thread.
   - Source: 5.1, 5.3, 5.4, 5.10
   - Applies to: Epic 6+ stories involving subprocess management

3. **Add structlog `event` kwarg to ruff custom rule or pre-commit hook.** The `event=` keyword clash with structlog is invisible at runtime and caught only by careful code review.
   - Source: 5.17b, 5.18
   - Applies to: all services using structlog

### Technical Debt

1. **Pre-existing check_imports violation in test_reasoning.py** — Priority: HIGH — Fix before Epic 6 starts to prevent further accumulation.
   - Source: Story 5.5

2. **~62 lines duplicated code between scripted worker stub and auto-approval stub** — Priority: LOW — Intentional fixture independence, but worth extracting shared utilities if a third stub appears.
   - Source: Story 5.18 (deferred)

3. **Incomplete JSONL line causes offset stall** — Priority: LOW — Pre-existing in worker stub, affects auto-approval stub too. No real-world impact for deterministic stubs.
   - Source: Story 5.18 (deferred)

4. **Transition log grows unboundedly** — Priority: LOW — By-design for finite worker lifecycle, but could be an issue for very long-running tasks.
   - Source: Story 5.17a (deferred)

### Team Agreements

- **Fix pre-existing violations on contact.** If a story's tests or code review touches a file with a pre-existing violation, fix it in the same story.
- **Event-level deduplication is the default.** New stubs or event consumers should use composite dedupe keys from the start, not task-level keys.
- **Callback-based DI for stateful infrastructure.** LifecycleManager pattern (callbacks for MCP/GitHub, no direct imports) is the standard for components that need testable state machines.
