# Epic 18 Retrospective: φ memory MCP server — the first store-backed server (Phase 3 Epic 5 of 6)

## Epic Summary

Epic 18 shipped `memory-mcp` — a persistent cross-task knowledge store backed by **SQLite FTS5**, a
**new archetype** (own store, not a subprocess sandbox or REST client). `read`/`search` (Tier-1),
`write` (Tier-2), emitting `memory.written`. Gated by ADR-0012. 5 stories, PRs #52–#55, all CI-green.
The first server to own a persistent backing file under P3-I2 store-isolation.

## Story-by-Story Highlights

- **18.1 + 18.2 (PR #52):** ATDD + the `MemoryStore`. **Two decisive design choices:** (a) **stdlib
  `sqlite3` + raw SQL, NOT SQLAlchemy** — FTS5 is SQLite-native (zero deps) AND raw `conn.execute`
  is not flagged by `check_single_writer` (which AST-detects only SQLAlchemy mutations outside
  registry-state); (b) **0o660/0o2775 file modes folded into store-init** per ADR-0012 §7 + the
  cross-uid umask memory — not a later point-fix. documents table + external-content FTS5 virtual
  table (trigger-synced) + bm25 ranking. P3-I2 isolation (own DB at `MEMORY_MCP_STORE_PATH`, never
  the registry DB) proven by a reference test.
- **18.3 (PR #53):** `read`/`search` Tier-1; also fixed a latent ATDD `_tool_fn` lookup bug the old
  xfails masked.
- **18.4 (PR #54):** `write` Tier-2 + `memory.written` (two-location, 1.1.0). **Payload is metadata-
  only** — `key`/`title`/`body_bytes` (the byte-length, an int — NOT the body). The document content
  lives only in memory's own DB; the queryable spine event can never carry it (ADR-0012 §5).
- **18.5 (PR #55):** S-8 separability (real subprocess + write→read round-trip) + allowlist
  (`MEMORY_MCP_*`, non-secret) + supply-chain; ADR-0012 finalized.

## Key Lessons (3 — applied to Epic 19's store)

### L1: Raw stdlib sqlite3 sidesteps the single-writer gate AND adds zero deps
The single-writer gate (`check_single_writer.py`) AST-detects SQLAlchemy mutation patterns outside
registry-state. A store-owning server using SQLAlchemy would trip it. Raw `sqlite3` with SQL strings
is invisible to the gate, needs no ORM dependency, and gives direct FTS5 access. This became the
store pattern for artifact-mcp (19) too.

### L2: Fold the file-mode (umask) fix into store-init from the start — never point-fix
ADR-0012 §7 explicitly cited the cross-uid umask-022 bug that crash-looped registry-state
*repeatedly* (it was point-fixed dir-by-dir, file-by-file across Stories 11.3.8–11.3.12). memory-mcp
created its DB + `-wal`/`-shm` at 0o660 + dir at 0o2775 **in `__init__`**, defensively chmod'd,
ignoring FileNotFoundError. The lesson from Phase-2's pain became a Phase-3 design precondition.

### L3: A store's spine event carries metadata, never the stored content
The `memory.written` payload is `key`/`title`/`body_bytes` — the body never enters the event. Spine
events are queryable and bounded-cardinality; cross-task knowledge content could be large or
sensitive. The bytes live only in the store. (artifact-mcp's `artifact.stored`/`artifact.deleted`
inherited this — metadata only, no content.)

  This is the value of ADRs that fold in prior-incident memory.
