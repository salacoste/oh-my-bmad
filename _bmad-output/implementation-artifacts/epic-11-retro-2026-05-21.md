## Lessons learned

### L1 — Cross-cutting HMAC stories require pass-2 review regardless of complexity estimate

**Pattern:** Story 11.3 (estimated MEDIUM), Story 11.4 (estimated LOW), Story 11.5 (estimated MEDIUM) all had pass-1 review catch real defects that executor's local testing missed:

- **11.3 pass-2:** 2 P0 regressions in pass-1 batch itself (operator-identity check broken because actor_id="http-api" in Phase 1; deterministic key + 410 unrecoverable loop)
- **11.4 pass-1:** 3 P0 regressions (hardcoded `action="approve"`, microsecond-precision mismatch breaking ALL real production events, transitive FastAPI imports falsifying "offline" claim)
- **11.5 pass-1:** 0 P0s but 2 P1-Hs (cross-restart race for "exactly-once", test filter masking future regressions)

**Conclusion:** Stories that touch HMAC/signing crypto OR span 3+ services OR introduce new audit invariants MUST pass through 3-lane adversarial review regardless of complexity estimate. Epic 9 retro AI-1 ("3-pass for high-complexity") is REINFORCED but the complexity estimate is not the right trigger — **the codebase-impact dimension is.**

**Action AI-1 (carry forward):** When story spec touches any of {HMAC, signing, key management, cross-service contracts, FR26 single-writer invariants, security/audit events}, mark for mandatory 3-lane review at spec-authoring time. Override executor's "1-pass review predicted" claim.

### L2 — Event log is SSoT; derived projections (SQLite) can lag

**Discovery:** Story 11.5 PD1 — rotation detector originally read from `KeyFingerprint` SQLite table (derived projection). Under cross-restart with subscriber-materializer lag, the detector saw stale data and emitted duplicate `key.rotated` events for one physical rotation.

**Resolution:** Detector now reads most-recent `key.rotated` from JSONL log (SSoT per arch_refs P2-I3 "derived projection rule"). SQLite is fallback for snapshot-restored deployments.

**Conclusion:** When implementing audit invariants ("exactly-once X event per Y"), the dedup invariant MUST consult the event log (SSoT), not the derived state projection. The state projection always exists for read performance; it's not authoritative for emission semantics.

**Action AI-2 (carry forward):** Audit existing materializers + detectors across all 13 epics — any read-then-write pattern that uses SQLite as the read source for an emission decision is a candidate for the same class of bug. Triage list goes to Epic 12 retro intake.

### L3 — Cross-story spec drift surfaces as latent debt

**Discovery:** Story 11.1's `compute_approval_hmac` docstring (lines ~50) said "if a future refactor moves this to packages/events, update Story 11.1 + this docstring in lock-step. Until then: registry-api import is correct." Story 11.4 pass-1 PP3 discovered the verifier transitively imported FastAPI/SQLAlchemy/Anthropic via the registry-api package — falsifying the "offline" claim. Fix: do exactly what Story 11.1's docstring anticipated (relocate to `packages/events/src/events/approval_signing.py`).

**Conclusion:** Latent debt anticipated by spec docstrings tends to come due unexpectedly. The story that authors the comment (Story 11.1) didn't have the trigger; the consumer story (Story 11.4) did.

**Action AI-3 (carry forward):** When spec-authoring identifies a "future refactor" condition in a docstring, ALSO file a backlog story tagged with the triggering condition. Don't trust comments alone to surface debt at the right moment.

### L4 — 3-lane adversarial review pays for itself

**Catch rate across Epic 11:**

| Reviewer | Independent P0/P1-H finds | Notable catches |
|---|---|---|
| Blind Hunter (diff only) | 4 P0/P1-H | Story 11.4 hardcoded action="approve" (also caught by others); Story 11.5 cross-restart race; Story 11.5 test filter masking |
| Edge Case Hunter (diff + codebase) | 4 P0 (Edge-alone) | Story 11.4 µs-precision mismatch; Story 11.4 transitive FastAPI imports; Story 11.5 env-var test pollution |
| Acceptance Auditor (diff + spec) | 2 P0 (spec-conformance) | Story 11.3 AC5 deferral surfacing; Story 11.4 hardcoded action (3-lane convergence) |

**Cross-lane convergence:** Story 11.4 hardcoded `action="approve"` was caught by Blind (P1-H), Acceptance (P0), and Edge (P1-L) — three independent readings of the same defect strengthens severity. The convergence was the strongest signal that the issue was real.

**Edge-alone wins:** Story 11.4's two NEW P0s (µs mismatch + transitive imports) required codebase context to spot. Blind/Acceptance both missed them. Story 11.5's env-var pollution P1-M similarly required reading sibling test files. **Without Edge in the lineup, both stories would have shipped with production-breaking bugs.**

**Conclusion:** Single-lane review (self-review or 1 reviewer) is structurally insufficient for cross-cutting stories. The cost of 3-lane parallel review (3 background agents) is negligible compared to the cost of post-ship P0 incidents.

**Action AI-4 (carry forward):** Codify 3-lane review as the DEFAULT for `/bmad-code-review` skill. No more "1-pass review predicted" auto-skip — predictable cadence > optimistic shortcuts.

## Process improvements adopted during Epic 11

1. **Background-agent reviewers** — Stories 11.3+ launched all 3 reviewers as background agents in parallel via `run_in_background=true`. Latency from review-trigger to findings-collected dropped ~3-4× vs sequential. Continue.
2. **`AskUserQuestion` for cross-story decisions** — Used for D1 (Story 11.5 cross-restart race resolution) and PD1-PD3 (Story 11.3 decision-needed batch). User input fast + cheap; preserves audit trail in spec.
3. **Spec amendment via deduplication** — Story 11.4's 3 D-decisions (D1-D3) all resolved as "amend spec to record shipped reality" rather than refactor working code. Cheap + honest. Continue for cosmetic spec-vs-impl drift.

## Anti-patterns to avoid (Epic 12+)

1. **"1-pass review predicted" claims at spec-authoring time** — Empirically wrong for cross-cutting stories. Skip the prediction.
2. **Self-review by executor** — Story 11.4 dev pass shipped 3 P0s the executor's own validation didn't catch. Adversarial 3-lane is mandatory.
3. **Reading from derived projection for emission dedup** — See L2. Always go through event log.
4. **Hardcoded test fixture shapes that drift from production** — See L6.
