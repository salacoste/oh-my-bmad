## Story-by-Story Narrative

### 2.1 — EventEnvelope + schema registry + canonical serializer (`37fede8` → `c5da0b4` → `b90f08e`)

The first real feature commit of the project after 11 stories of scaffold. Pydantic v2 frozen+strict envelope, `(type, schema_version) → payload_model` registry, byte-deterministic canonical JSON serializer, typed exception hierarchy. Three-layer review surfaced 3 CRITICAL bugs that all required runtime probes to find: (1) `EVENT_TYPES` was imported at module load, so when `register()` rebuilt the cache the importer held a stale empty value — `EventSchemaUnknown.registered_types` always reported `(empty registry)`, a P0 observability bug on the FR21/NFR-O5 path; (2) canonical round-trip was not byte-stable on `+00:00` inputs; (3) payload dicts were mutable via reference (`env.payload["k"]=v` succeeded). All three would have shipped clean against the dev pass's "all tests green" report. Test count rose 75 → 158 across the scaffold + review-fix.

### 2.2 — UUIDv7 + injectable clock (`103d13a` → `f09a9e0` → `ee3191f`)

Hand-rolled RFC 9562 v7 implementation (~20 lines of bit-shifting), `Clock` Protocol with `SystemClock`/`FrozenClock`/`TickingClock`. Spec-sketch sufficiently concrete that the executor (Sonnet 4.6) shipped clean-room with zero deviations. Review still found 3 CRITICAL: (1) `TickingClock._tick_us = tick_ns // 1000` silently zeroed for `tick_ns<1000`, so two readings of "the same" clock disagreed about time-ordering; (2) `parse_prefix` accepted arbitrary 36-char garbage after `t-/s-/e-`; (3) `new_uuid7` timestamp extraction used float arithmetic on a potentially-naive datetime → identical fixtures produced different UUIDs on different timezones. Fix-pass shipped integer-only `(now - epoch) // ms` arithmetic. `seeded_uuid7` fixture switched from `FrozenClock` to `TickingClock(start_now=FROZEN_EPOCH)` so consecutive calls produce strictly time-ordered UUIDs. Tests 158 → 206.

### 2.3 — Registry-state SQLite schema + Alembic initial (`cc915d2` → `f139dca` → `4ad6612`)

5 SQLAlchemy 2.x models, async engine factory with connect-time pragmas (WAL + synchronous=NORMAL + foreign_keys=ON + busy_timeout=5000), Alembic async env. Two CRITICAL bugs were *false-passes* in the dev pass — the executor's tests reported green but empirical reviewer probes proved the tests were structurally unable to fail: (1) `UTCDateTime.process_bind_param` used `value.replace(tzinfo=None)` instead of `value.astimezone(UTC).replace(tzinfo=None)` — a non-UTC tzinfo input was stored as wall-clock and read back as UTC, 5 hours in the future. Silent data corruption. (2) `read_only=True` URL rewrite appended `?mode=ro&uri=true` to the URL, but aiosqlite ignores URL `uri=true` — phantom SQLite files were created in `/tmp` and the "read-only" engine opened a fresh writable empty DB at the bogus path. `test_read_only_engine_rejects_writes` was a false pass — the OperationalError fired because the phantom DB had no `tasks` table, not because writes were rejected. Both classes of false-pass set the precedent for empirical-probe verification in every subsequent review. Tests 206 → 230.

### 2.4 — Event-log JSONL append writer (`7d8d9b3` → `d7f6238` → `8ec2891`)

Stdlib-only writer (`os` + `pathlib` + `asyncio.to_thread`), canonical-JSON-first serialization, `fdatasync` after every write, single-`write()` under `O_APPEND` relying on Linux ext4/XFS inode-lock atomicity (no temp-file-rename). Review found 1 CRITICAL + 7 MAJOR: (1) `os.write` short-write on ENOSPC/EINTR left a half-JSON line on disk; the next `append()` concatenated to the half-line → corrupt JSONL; fix added a poison-pill flag that requires `recover()` to clear. (2) `recover()` only trimmed today's file — a crash at 23:59:59 leaving yesterday's file with a partial tail and a restart at 00:00:01 would leave the partial tail forever. Fix iterates `base_dir.glob("*.jsonl")`. (3) Parent-dir fsync after `ftruncate` — without it, a power-cut after `recover()` could resurrect the partial tail because the metadata change wasn't durable. (4) `read_log_lines` deferred `FileNotFoundError` to first iteration (generator contract violation). (5) CRLF tolerance via `rstrip(b"\r\n")`. File mode tightened to `0o640` (audit-log best practice; was `0o644`). Tests 230 → 261.

### 2.5 — Event-log subscriber + state materializer (`e45a4fa` → `33b8e70` → `bc700f7`)

The first concrete event types — `task.created`, `task.planning.started`, `task.plan.ready`, `task.execution.started` — registered via Story 2.1's `register()` API. Materializer dispatches by event type with `INSERT … ON CONFLICT DO NOTHING` for idempotency by `event_id` PK. The 1-second live-tail SLA (AC-8) is verified by booting the subscriber in a task, appending an envelope, polling `tasks` table at 50 ms intervals for up to 1000 ms. The subscriber loop also computes the resumable cursor as `MAX(events.emitted_at_monotonic_ns)` and skips already-applied envelopes during startup replay. The "3× replay byte-identical" property is verified at this story's scope; the 100× version lives in 2.13. Tests 261 → 286.

### 2.6 — Snapshot capture + replay on startup (`2b51628` → `e29d721` → `f83307d`)

`SnapshotPolicy` captures every N events (default 1000); `restore_state_from_latest_snapshot` UPSERTs into `tasks` + `sessions` from the snapshot's payload; `compute_replay_cursor` returns `max(snapshot_cursor, MAX(events))`. The HIGH-RISK flag from architecture line 834 was honored with a CRITICAL review finding: `update_set = {k: v for k, v in row.items() if k != "id"}` overwrote `created_at` on UPSERT collision — the live row's creation timestamp was clobbered by the snapshot's. Fix excludes both `id` and `created_at` from the UPDATE clause. Other MAJORs: `maybe_capture` while-loop produced byte-identical duplicate snapshots when batches exceeded 2× the interval; `ORDER BY created_at DESC LIMIT 1` ties were non-deterministic on FrozenClock (added `Snapshot.id.desc()` secondary sort using UUIDv7 monotonicity); orphan-session validation gives operator-friendly errors instead of raw `IntegrityError("FOREIGN KEY constraint failed")`. The BDD "byte-for-byte equivalence between full-replay and snapshot-replay" test is the AC-headline. Tests 286 → ~315.

### 2.7 — Idempotency cache (`f52e991` → `58c7dd5` → `2f5ccd6`)

`cachetools.TTLCache` (in-process) + SQLite `idempotency_cache` table (durability), per-key `asyncio.Lock` via `WeakValueDictionary` so concurrent same-key callers serialize behind one factory invocation. Review found 4 CRITICAL: (1) **The `WeakValueDictionary` GC race actually breaks per-key serialization** — the lock is held by a strong ref only for the lifetime of `get_or_run`'s local variable; after return, GC can reap the lock. Sustained-load (50 calls → GC → 50 more) can have parallel callers create different locks → factory runs multiple times → NFR-R4 violated. The 100× test masks this because all 100 callers spawn simultaneously. Fix replaced WVD with `dict[str, asyncio.Lock]` + explicit refcount cleanup. Added a sustained-burst test (50 + GC + 50 same key, asserting `factory_call_count == 1`). (2) `cachetools.TTLCache` ignored the injected Clock — measured TTL with stdlib `time.monotonic()`. With FrozenClock, in-process expired on real wall time while SQLite expired on frozen-clock time → stale-data leak. Fix passes `timer=lambda: self._clock.now().timestamp()`. (3) The `IdempotencyConflict` test was manufactured (mocked `fetchone() → None`); rewritten to interleave a real `sweep_expired` between the UPSERT and SELECT. (4) Three `# noqa: SW001` suppressions in cache.py contradicted AC-14's explicit instruction to update the scanner exclusion list — `packages/idempotency/` was added to `_EXCLUDED_ROOTS`. Tests grew by ~18.

### 2.8 — clawhip-bridge MCP server (`49b7803` → `947ec34` → `43f24cb`)

5 append-only emission tools (`emit_event`, `emit_blocker`, `emit_summary`, `emit_approval_request`, `emit_completion`) + 1 read-only `recent_events` resource over MCP stdio. 4 new event types registered: `task.blocker_raised`, `task.summary_emitted`, `task.approval_requested`, `task.completed`. Review found 5 CRITICAL of which the most damning was that **all 11 emit-tool tests bypassed the FastMCP runtime entirely** — they reached into `mcp._tool_manager._tools["emit_event"].fn` and called the underlying coroutine directly, never through `await mcp.call_tool(...)`. The lifespan hook (recovery), JSON-schema arg coercion, Tool→MCPTool wrapping, and JSON-RPC error envelope were all unexercised. AC-1's "tool emits to log" was verified at the unit-coroutine level, not at the MCP-protocol level. Lifespan recovery (AC-6) was never tested. Fix added at least one integration test that drives the full FastMCP runtime. Other CRITICALs: missing `*` keyword-only separator in all 5 tool signatures (AC-1 spec violation); `_check_tier` return value discarded by all 5 callers (future-bug landmine when Story 6.1 implements actual tier enforcement). Tests grew by ~14.

### 2.9 — Registry-api HTTP skeleton (`56e44b7` → `38d0744` → `db23572`)

### 2.10 — Failure-detection typed events (`0c3e841` → `9a8f741` → `6fd4d3b` → `64389d9`)

4 new payload models + registrations: `service.crashed`, `session.heartbeat_timeout`, `sink.delivery_failed`, `task.stop_requested`. `HeartbeatMonitor` and `SinkFailureTracker` helper classes. Two-round review (round 1 commit `9a8f741` + round 2 `6fd4d3b`): round 1 fixed 0 CRITICAL / 18 MAJOR / 25 MINOR; round 2 picked up edge-case findings the first pass deferred. The MAJOR finding that propagated furthest was the **canonical `Actor.kind` set** — the spec used `kind="service"` but `ActorKind` is `Literal["operator", "orchestrator", "worker", "system", "clawhip"]`. Fix kept `kind="system"` for detector-emitted events but added an `actor_kind` parameter to `emit_task_stop_requested` so operator-initiated stops can use `kind="operator"`. The `Actor.id` for `service.crashed` defaults to the `service` parameter (the crashing service IS the actor; registry-state is only the detector). `should_emit` was made edge-triggered (`_emitted_at_count` tracks last emit checkpoint) so a streak past threshold across polling ticks doesn't re-emit on every tick. `record_heartbeat` ignores clock regressions. `last_error` now passes through `_redact_last_error` (defense-in-depth on top of caller sanitization). Tests grew by ~21.

### 2.11 — Synthetic crash-injection harness (`c221fad` → `b82a8e6` → `48a1326`)

Pytest harness that boots registry-state under docker compose, drives a task through 4 lifecycle phases (`PLANNING`, `EXECUTING`, `AWAITING_APPROVAL`, `VERIFYING`) by appending synthesized events, kills the host with `compose stop --timeout 1` (Linux) or `kill --signal SIGKILL` (macOS), restarts, and asserts state-reconstruction with zero duplicates. Round-1 review found 6 CRITICAL: (1) **the test had a semantic gap that defeated its own purpose** — pre-kill `wait_for_materialization` was materializing events before the kill, so the post-restart assertions verified durability not JSONL replay. Fix dropped the pre-kill wait entirely; sequence is now strictly append → kill → restart → wait → assert. (2) `Base.metadata.create_all` in production startup bypassed Alembic — the test docker overlay had quietly stitched in a non-Alembic schema-create step that conflicted with the canonical migration source. Fix gated behind `REGISTRY_STATE_AUTO_CREATE_SCHEMA=1` set only in the test overlay; production schema is via Alembic (Story 2.14). (3) Nightly workflow lacked `extractions/setup-just@v2` step. (4) Empty `ids_jsonl` produced invalid SQL `IN ()`. (5) Per-task duplicate assertion accumulated across phases (a global `count_jsonl == count_db` didn't catch per-task duplicates) — fix added per-task `json_extract(payload_json, '$.task_id')` count alongside the global invariant. (6) Test order dependency under `pytest-randomly` — fix added `pytest_collection_modifyitems` hook pinning the 4 phase tests in declaration order. 17 MAJOR + 11 MINOR followed. The harness now produces a JSON summary artifact with per-phase pass/fail counts.

### 2.12 — Atomic-edit primitive + write-interrupt harness (`e77b666` → `fb7ece9` → `f6c2e12`)

Standalone `atomic_write_bytes(target, data, *, fsync_data=True, fsync_dir=True)` in `services/worker-wrapper/` — write to sibling tmpfile (`<target>.tmp.<pid>.<16-hex>`), fsync, `os.replace`, fsync parent directory. Cross-filesystem detection via `OSError(EXDEV)` re-raise with a clear message. The 100-iteration randomized-kill-offset test spawns a subprocess driver that monkey-patches the module's `_chunked_write` and `os._exit(137)` after a configured byte threshold; assert the target file's content hash matches **either** the pre-edit hash **or** the post-edit hash, never any other value. After review-fix M2 (`_POST_EDIT_CONTENT` widened to 100,000 bytes so kill offsets cross 64 KB chunk boundaries) and M3 (kill range widened to `[0, n_total*2)` so ~50% of trials land past `n_total` and exercise the no-interrupt rename path), the empirical outcome was **47 pre-edit, 53 post-edit, 0 partial**. Other MAJORs: `secrets.token_hex(4)` bumped to `token_hex(8)` (32 → 64 bits, eliminates birthday collision at 65k concurrent writers); `dir-fsync` failure post-rename now logs and suppresses (data is on disk; raising would mislead callers into double-write retries); file-mode preservation via pre-write `os.stat`+post-rename `os.chmod` so atomic-write doesn't reset 0o644 to 0o600. Tests grew by ~12 fast + ~5 slow.

### 2.13 — Idempotency 100× replay test (`4342655` → `2d8ab58` → `b7b6e10`)

Wired `IdempotencyCacheStore.get_or_run` into `POST /v1/tasks`. Concurrent same-key calls serialize behind the per-key lock; factory runs exactly once; all 100 responses are byte-identical 201s. `X-Idempotency-Status` header reflects `applied | replayed`. Review-fix found 3 CRITICAL: (1) `response_body_cache` was populated OUTSIDE `_factory()` — concurrent loser callers could observe an empty cache and fall into the post-restart fallback path. Fix moved population inside the factory body so the per-key lock protects it. (2) `Location` header was `/v1/tasks/` (malformed) on the post-restart fallback path. Fix omits the header and adds a `Warning: 199 oh-my-bmad ...` signaling degraded reply. (3) The `response_body_cache` was an unbounded `dict[str, bytes]` — OOM vector. Fix wrapped in `cachetools.TTLCache(maxsize=100_000, ttl=604_800)`. (4) Most damning for the project's overall rigor: `mypy.ini` had `[mypy-tests.*] ignore_errors = True` which silenced ALL test errors — AC-13's "mypy strict on tests/idempotency/" was vacuously green. Reviewer verified by injecting a deliberate `int = "string"` and confirming mypy then caught it. Per-directory overrides re-enable strict on `tests/idempotency/` and `tests/crash-injection/`. M8 (dual writable engines targeting the same SQLite file) was DEFERRED to a follow-up story. Tests grew by ~18 with 10 parametrized iterations producing localized flakiness signals.

### 2.16 — secret.accessed audit event + AuditedSecret wrapper (`669327b` → `c32d2b8` → `21372fe` → `a9b9392`)

`SecretAccessedPayload` (frozen, strict, `secret_name` 1..128 chars, `scope: Literal["read"]`); registered under v1.0.0 + v1.0.1. `AuditedSecret` class with `__slots__` and redaction-aware `__repr__`/`__str__` (returns `<REDACTED:secret_name>`). `.value` property is synchronous (Python attribute-access semantics) but emission is async — resolution is fire-and-forget via `asyncio.get_running_loop().create_task(emit(envelope))`; if no loop is running, log a WARNING and skip. `audited_secret_field()` returns a Pydantic `Field` carrying `json_schema_extra={"audited_secret_name": ...}` and optional `validation_alias` for env-var override. `AuditedBaseSettings` extends `pydantic_settings.BaseSettings` with `arbitrary_types_allowed=True`, a `model_validator(mode="before")` pre-coercing strings → placeholder `AuditedSecret`, and a `from_env(emit, actor, clock)` classmethod that walks marked fields and rewraps with the real callbacks. The three-layer review pass found **7 High / 10 Medium / 14 Low** — the dev pass had reported "all green" with 558 passed/2 skipped; the review revealed:

- **H1 (CRITICAL on re-read):** `AuditedSecret` had no `__get_pydantic_core_schema__`, so `model_dump()` / `model_dump_json()` leaked `_value` directly. Fix added a plain-validator + serializer schema that always returns `<REDACTED:secret_name>`.
- **H2:** `loop.create_task` could raise `RuntimeError` on a closed loop; wrapped in try/except with WARNING log + value still returned.
- **H3/H4:** `from_env` now raises `ValueError` for empty-string and `None` env-var resolutions (fail-fast UX over silent acceptance).
- **H5:** Bare `MySettings()` reads (without `from_env`) now warn once-per-instance via a `_UNCONFIGURED_ACTOR` sentinel — caught the case where dev code grabs the value without wiring audit.
- **H6:** `flush_pending_emissions(timeout)` module helper for graceful service shutdown of in-flight emissions.
- **M1:** `_safe_emit` now lets `KeyboardInterrupt`/`SystemExit`/`asyncio.CancelledError` propagate (was silently swallowed).
- **M3:** `_AUDITED_FIELD_MARKER` sentinel — foreign code that happened to use the same dict key but no marker is no longer wrapped.
- **M4:** `_UNSET` sentinel distinguishes "no default" (required) from `default=None` (optional with literal None default).
- **M8:** `__pydantic_init_subclass__` enforces `secret_name` uniqueness across audited fields (fail-fast at class-definition time).
- **M10:** `ContextVar`-based re-entrant emission guard prevents unbounded fan-out when an emit callable itself reads an `AuditedSecret`.
- **M11:** `_live_emission_tasks` is a `weakref.WeakSet` (auto-cleans GC'd tasks) plus an explicit anchor preventing the asyncio weak-ref GC race.
- **L25:** GC-anchor invariant test (force `gc.collect()` mid-flight, then flush).

Tests grew 558 → 582 (+24). The schema-registry teardown collision (`packages/events/src/events/test_envelope.py::_clean_registry` clearing REGISTRY between tests) was hit during initial implementation and resolved with a function-scoped autouse fixture re-installing the registration. The `uv sync` venv churn (between `bootstrap-verify --no-dev --frozen` and the dev-bound test recipes) was hit during regression and recovered via `uv sync --all-groups --all-packages`.

- **M8:** Whitelist case-sensitivity asymmetric with sanitizer's `.casefold()` — documented as Action Item; harness contract is lowercase-only for now.
- **M9:** Custom-object `__repr__`/`__str__` leak channel not scanned; documented gap.

## What Went Well

1. **Single-writer + append-only persistence shipped clean and stayed clean.** Stories 2.3 (SQLite schema), 2.4 (JSONL writer), 2.5 (materializer), and 2.6 (snapshots) form a four-story arc that landed FR20 + FR24 + FR25 + FR26 without re-architecting any earlier story. The decision to write canonical-JSON-first (2.4 AC-2) and use `fdatasync`-not-`fsync` (2.4 AC-4) survived the review pass. ext4/XFS inode-lock atomicity under `O_APPEND` (2.4 AC-5) eliminated the temp-file-and-rename dance for the append path — a deliberately small, defensible decision.

2. **The crash-recovery story actually proves crash recovery.** Story 2.11 boots the registry-state container under docker compose, kills the host with `compose stop --timeout 1` (Linux) or `kill --signal SIGKILL` (macOS), restarts, and asserts post-restart state-reconstruction with zero duplicates across 4 lifecycle phases (commits `c221fad`, `b82a8e6`). The review caught a CRITICAL semantic bug in the test itself (C1: pre-kill wait was materializing events before the kill, making the post-restart test verify durability not replay) — the fix sequence is now strictly append → kill → restart → wait → assert.

3. **NFR-R4 is a 100× CI fact, not a belief.** Story 2.13's `test_idempotency_100x_concurrent_same_key_yields_one_task_and_identical_responses` (commit `4342655`) drives 100 concurrent same-key POSTs and asserts exactly 1 task row + 100 byte-identical 201 responses. The 10-iteration parametrize was chosen over a loop so a flaky run localizes to a specific iteration in pytest output.

4. **NFR-M5 separability is a one-env-var fact.** Story 2.15's null-orchestrator fixture (commit `a8c71ea`) drops a pass-through orchestrator into the compose stack via `ORCHESTRATOR_IMAGE=null-orchestrator:latest`, walks a task `created → completed`, and a companion `git diff` test pins the spine source code unchanged. FR35 is now CI-verified.

5. **Three-layer adversarial review caught real defects the dev pass missed.** Stories 2.16 (commit `c32d2b8`) and 2.17 (commit `13fe0a2`) used Blind Hunter + Edge Case Hunter + Acceptance Auditor in parallel. 2.16 surfaced a `model_dump_json()` redaction-bypass leak (H1) the dev pass shipped clean lint with; 2.17 surfaced a 24-character-of-leaked-secret echo in the harness's own failure path (H2 — the harness violated the very contract it enforced). Both were corrected before review→done.

6. **Story 2.10's `Actor.kind` Literal canonical set paid off three stories later.** When 2.16's spec used `kind="service"` (a typo against the `operator | orchestrator | worker | system | clawhip` Literal established in 2.10), the issue was caught at spec-read time (AC-7 of 2.16 documents the typo and uses `worker`/`system`). Story-to-story memory worked exactly as planned.

7. **Stdlib-only choices held up.** Story 2.4's writer (no `aiofiles`, just `os` + `asyncio.to_thread`); Story 2.6's snapshots (no separate snapshot library); Story 2.12's atomic-write (no `atomicwrites` package, just `os.replace` + fsync). All three avoided third-party dependencies for workloads that are fsync-serialized (single-writer per FR26) and where the stdlib primitives are precisely the correct tools. Zero regrets in the review pass on any of these choices.

8. **The migrator's additive-version pattern (2.14) generalized.** Registering all 12 event types under both v1.0.0 AND v1.0.1 (REGISTRY went from 12 → 24 entries with the same payload models) exercised 2.1's `register()` idempotent-same-model contract under realistic load. The CI gate philosophy (architecture-as-code, not architecture-as-PDF) paid off.

10. **The `services/registry-state/` exclusion in `check_single_writer.py` did exactly what it was designed to do.** The single-writer discipline (FR26) is proven mechanically: every story that needed to mutate SQLite either lived under `services/registry-state/` (was the materializer or a sibling) or went through a typed event. ## What Struggled

1. **Dev-pass executors over-reported readiness — review consistently surfaces 20+ findings.** Story 2.16's dev pass reported "8/8 lint, 558 passed/2 skipped" and the three-layer review then surfaced 7 High / 10 Medium / 14 Low. Story 2.17's dev pass reported "8/8 lint" but `tests/integration/test_log_capture.py` was never added to the secret-hygiene allowlist — the original commit's lint actually failed; the reviewer caught it. The dev pass cannot be trusted to self-certify completion; the review pass is mandatory before flipping `review → done`.

2. **`uv sync` venv churn cost real cycles.** `bootstrap-verify` runs `uv sync --no-dev --frozen`, which uninstalls dev-only deps (`asgi-lifespan`, `sniffio`) needed by `tests/idempotency/test_100x_replay.py` and `services/registry-api/.../test_app.py`. Stories 2.16 and 2.17 both hit this and recovered via `uv sync --all-groups --all-packages`. It is a venv-state side effect of running `--no-dev` between two dev-bound recipes; it does not represent a code defect, but it interrupts the dev loop until you know the recipe.

3. **Schema-registry test-isolation pattern was re-discovered twice.** `packages/events/src/events/test_envelope.py::_clean_registry` is an autouse fixture that clears `REGISTRY` between cases. 4. **structlog vs stdlib `logging` confusion surfaced in 2.16 and was deliberately accepted as a documented gap in 2.17.** Story 2.16's review pass discovered that `caplog` cannot capture structlog warnings without a bridge; the partial fix routed `audited_secret`'s WARNING/ERROR through stdlib `logging.getLogger("secret_hygiene.audited_secret")`. A future story may want a unified harness; today the gap is explicit, not silent.

5. **Code-review "round 2 deferred items" became a recurring third commit per story.** Story 2.10 closed with `9a8f741` (round 1) → `6fd4d3b` (round 2 edge-case findings); 2.15 with `4c094e2` (round 1 partial) → `9553b31` (round 2 deferred items). The pattern indicates the reviewer's first pass picks the highest-value findings; a second pass picks the items "deferred" from the first. This is not a defect in the review process — it's evidence the dev pass leaves enough surface area that a single review pass cannot exhaust it. Budget for two review-fix commits on any non-trivial feature story.

6. **Docker availability skip semantics needed two refactors.** Story 2.11 introduced `_skip_if_no_docker` as an autouse fixture via leading-underscore-positional. Story 2.12's write-interrupt tests don't need Docker, so they refactored to explicit-opt-in (Story 2.12 AC-11). The pattern is now: each test tree owns its own `skip_if_no_docker` (Stories 2.11, 2.14, 2.15 each have one).

7. **Slow tests are slow enough to interact with the dev loop.** The crash-injection harness budgets 60s per phase × 4 phases = up to 4 minutes. The 100-iteration write-interrupt test budgets 30s. The S-3 separability test budgets 30s for the end-to-end + image-build cold path. 8. **The dev pass shipped lint-fail commits twice.** Story 2.16 reported "8/8 lint" but a probe of the original commit revealed the secret-hygiene allowlist was missing the new test file. Story 2.17 had the same shape (lint claimed green; reviewer caught it). In both cases, the reviewer ran `just lint` independently and got a fail. Either the dev pass executed lint against a stale virtual environment, or the executor reported claimed status from a partial run, or the lint output was misread. ## Cross-Cutting Architectural Discoveries

These are decisions, observations, and surprises that emerged across multiple stories rather than within a single one. They are worth flagging for Epic 3 onward.

### The "false-pass" failure mode is real and common

Stories 2.3 (`read_only` URL rewrite, `UTCDateTime.process_bind_param`), 2.7 (`IdempotencyConflict` test mocking `fetchone() → None`), 2.8 (all 11 emit-tool tests bypassing FastMCP), 2.11 (pre-kill wait defeating reconstruction), and 2.13 (`mypy.ini ignore_errors=True`) all shipped tests that were structurally unable to fail. The dev pass reported green because the assertions were satisfied — but the assertions weren't testing what the AC said they were testing. Empirical reviewer probes (running real SQLite, real aiosqlite, real FastMCP, deliberate type errors) caught five distinct false-pass classes. The lesson: **assertion presence is not the same as assertion meaningfulness**. The three-layer review pass survives this failure mode where unit-level dev-pass introspection does not.

### Stdlib-only is the right default for fsync-serialized workloads

Three stories (2.4, 2.6, 2.12) explicitly chose stdlib over `aiofiles` / `atomicwrites` / specialized libraries. The rationale in each case: (a) the workload is single-writer per FR26, so the threadpool / blocking-syscall overhead doesn't accumulate; (b) the syscalls (`os.write`, `os.fsync`, `os.fdatasync`, `os.replace`, `os.ftruncate`) compose precisely with the durability semantics each story requires; (c) third-party wrappers add a dependency surface (and version-skew risk) without earning their keep at this scale. None of the three review passes flagged the stdlib choice as suboptimal; in fact 2.4's review specifically commended `asyncio.to_thread` over `aiofiles` for simplicity. Continue this default through Epic 5 (worker-wrapper file ops).

### `asyncio.Lock()` constructed at `__init__` is safe on Python 3.12

Multiple stories construct `asyncio.Lock()` in synchronous `__init__` outside any running event loop (Stories 2.4 EventLogWriter, 2.6 SnapshotPolicy, 2.7 IdempotencyCacheStore, 2.16 AuditedSecret task tracking). Pre-Python-3.10 this was risky (the lock bound to whichever loop happened to be running at construction); Python 3.12 fixed this — locks are loop-bound at first acquisition. Multiple review passes flagged this as a potential issue (each marked MINOR with a "safe on 3.12" note) before being dismissed. The lesson: the codebase's `python>=3.12` pin is load-bearing; downgrading would silently re-introduce a class of subtle async bugs.

### UTC-everywhere with `tzinfo` guards at every boundary

Stories 2.1 (`emitted_at` field validator), 2.3 (`UTCDateTime` TypeDecorator), 2.4 (`current_day_path` UTC-only), 2.10 (`SessionHeartbeatTimeoutPayload.last_heartbeat_at` AwareDatetime), 2.16 (Actor.kind enforcement) each added a tzinfo guard at their respective layer. The pattern (`if dt.tzinfo is None or dt.utcoffset() != timedelta(0): raise ValueError(...)`) is repeated verbatim across stories. There is no central UTC-guard helper because the layers each need slightly different error messages and validation timing — co-locating the guard with the validation is correct. The lesson: this is one architectural invariant where duplication beats abstraction.

### Test-tree mypy-strict discipline took three stories to converge

- Story 2.13 added `[mypy-tests.*] ignore_errors = True` (vacuously green).
- Reviewer C4 caught it; per-directory overrides re-enabled strict on `tests/idempotency/` and `tests/crash-injection/`.
- Story 2.14 followed up with `[mypy-tests.migrator.*] ignore_errors = False`.
- Story 2.15 added `[mypy-tests.separability.*] ignore_errors = False`.

The convention is now: every new test tree under `tests/` gets a `[mypy-tests.<tree>.*] ignore_errors = False` override AND is added to the second mypy invocation in the `lint` recipe. Document this in `CONTRIBUTING.md` so Epic 3's first new test tree (likely `tests/telegram/` or `tests/integration/`) follows the convention without re-discovery.

### `tests/conftest.py` is not discoverable from `services/**`

This was discovered in Story 2.4 (test_event_log.py couldn't see `fixed_clock` / `seeded_uuid7` from the top-level conftest) and propagated cleanly through 2.5, 2.6, 2.10, 2.11. Each story inlines fixture re-declarations rather than re-engineering pytest fixture-discovery scope. The deviation is documented in 2.4's Change Log; subsequent stories cite "matching Story 2.4 convention". This is a known and accepted limitation of the test layout — `tests/conftest.py` works for tests under `tests/`; co-located `services/<svc>/src/<svc>/test_*.py` need their own fixtures or inlined helpers.

### Schema-registry teardown collision pattern

`packages/events/src/events/test_envelope.py::_clean_registry` is an autouse fixture that clears `events.schema_registry.REGISTRY` between cases. Tests that depend on previously-registered event types (notably 2.16's `secret.accessed` and 2.17's harness invariants) must add a function-scoped autouse fixture that re-installs the registration on every test, with idempotency guards against the canonical registry-state-side population already running. Both 2.16 and 2.17 hit this independently; the pattern is now load-bearing for any test that loads a non-trivial event type from outside the original registration site. **Action Item 5 captures the documentation work.**

### `uv sync --no-dev --frozen` strips dev deps the test suite needs

`bootstrap-verify` runs `uv sync --no-dev --frozen` to verify the production runtime deps are coherent. This uninstalls dev-only deps including `asgi-lifespan` and `sniffio`, both of which `tests/idempotency/test_100x_replay.py` and `services/registry-api/.../test_app.py` import. Recovery is `uv sync --all-groups --all-packages`. Hit independently in 2.16 and 2.17 during regression; **Action Item 4 captures the docs work.**

### Round-2 review-fix commits are normal, not exceptional

Stories 2.10 (`9a8f741` round 1 + `6fd4d3b` round 2) and 2.15 (`4c094e2` round 1 + `9553b31` round 2) closed via two review-fix commits. The first round picked highest-value findings (CRITICAL + most MAJOR); the second picked the deferred items. This is not a defect in the review process — it's a signal that any non-trivial story leaves enough surface area that a single review pass cannot exhaust it. **Budget for two review-fix commits on any non-trivial feature story.** Not every story needs round 2 (2.16 closed in one round despite 7 High findings); the threshold is empirical.

### Scanner exclusion for `packages/idempotency/`

Story 2.7 introduced the first place where a writer outside `services/registry-state/` legitimately needs to write SQLite (the cache writes to its OWN cache table, not to `tasks/sessions/events`). The dev pass attempted to suppress with `# noqa: SW001` (3 instances); the reviewer (2.7 CRITICAL F4) caught the AC-14 violation and the fix added `packages/idempotency/` to `_EXCLUDED_ROOTS` in `check_single_writer.py` with a clarifying comment. **Story 2.13 then re-confirmed this was the correct call** — when `IdempotencyCacheStore` was wired into registry-api's POST handler, the gate stayed green because the cache lives in `packages/idempotency/`, not registry-api. The exclusion is the right architectural mechanism, not the noqa.

## Appendix B — Key Decisions That Survived Review

These decisions were proposed in the spec, defended by the dev pass, scrutinized by review, and survived. Worth flagging because they constrain Epic 3+ design:

1. **Single-`write()` under `O_APPEND` is the writer atomicity contract** (2.4 AC-5). No temp-file-rename for append. Relies on Linux ext4/XFS inode-lock atomicity. Documented in module docstring; reviewer agreed it's not POSIX-formally-guaranteed for regular files but is empirically guaranteed on the production target.

2. **`fdatasync` not `fsync`** (2.4 AC-4). 10-30% faster on ext4/XFS; identical durability for the use case (we don't care about inode mtime). Documented choice; review did not push back.

3. **In-process cache is an optimization; SQLite is source of truth** (2.7 AC-6). Write-through pattern: SQLite first (durability), in-process second. If SQLite write fails, in-process is NOT touched. Survived 4 CRITICAL review findings without changing the layering.

4. **`201 Created` on idempotency replay, not `409 Conflict`** (2.13 Dev Notes). Architecture line 318 originally drafted 409; spec mandated 201 for the 100× test invariant. Decision documented; flagged for retro-confirmation; **Action Item 8** captures the architecture-doc amendment.

5. **`packages/idempotency/` writes its own cache table** (2.7 AC-14). Not a violation of FR26 single-writer — the cache is a separate concern from materialized event-log state. Scanner exclusion added explicitly; not silenced via `# noqa: SW001`.

6. **`AuditedSecret.value` is synchronous + fire-and-forget emission** (2.16 AC-2 Option A). Sync contexts log a warning and skip emission; not forced async (would break all sync callers like `config.api_key`); not threaded (over-engineering). Survived H2 review by adding closed-loop guards.

7. **Log whitelist lives in `tests/_log_capture.py`, not `packages/events/`** (2.17 Dev Notes "Whitelist source-of-truth — Decision"). Co-located with the harness; documented as canonical until services start emitting structured logs. Reviewer agreed; deferred to a future consolidation story.

8. **`FrozenClock` vs `TickingClock`** (2.2 review F4). `FrozenClock` returns the same datetime on every call; `TickingClock` advances by `tick_ns` per call. The `seeded_uuid7` fixture uses `TickingClock` so consecutive UUIDs are strictly time-ordered. The split-class design (rather than one configurable Clock) survived review and is now the canonical test-double for time-dependent behavior.

9. **No new conftest fixtures** (2.4 AC-13, propagated to 2.5/2.6/2.10/2.11). Co-located fixture re-declarations beat re-engineering pytest's discovery scope. Documented deviation; not reopened in any subsequent review.

10. **JSONL tailing for the null orchestrator** (2.15 Dev Notes "JSONL tailing vs MCP subscription"). Pragmatic: the null orchestrator is a test fixture; MCP-client plumbing would significantly inflate scope. Survived review; production orchestrators (Epic 5) will use proper task-state queries.

## Appendix E — Carry-forward Risk Register

Epic 2 documented these risks; none currently materialize but each could surface during Epic 3+:

- **R1 — Dual writable SQLite engines under load** (2.13 review M8). Registry-api owns `idempotency_cache` writes; registry-state owns `tasks/events/sessions` writes. Same SQLite file. WAL permits ONE writer transaction at a time database-wide. Under sustained ≥100 RPS load this would surface as `OperationalError: database is locked`. **Likelihood Phase 1: low** (single-operator, low RPS). **Mitigation**: separate idempotency-cache into its own SQLite file (architectural change). Tracked as a follow-up story. Action Item 7 captures the architect-pass.

- **R2 — Schema-registry teardown collision in unrelated tests** (2.16, 2.17 hit it). The `_clean_registry` autouse in `test_envelope.py` clears REGISTRY between cases; tests in unrelated modules that load registered event types must re-register. **Likelihood**: high — every Epic 3 story that introduces a new event type will hit this if it co-locates tests. **Mitigation**: Action Item 5 — document the pattern in `tests/README.md`.

- **R3 — `uv sync --no-dev --frozen` strips dev deps the test suite needs** (2.16, 2.17 hit it). Recovery: `uv sync --all-groups --all-packages`. **Likelihood**: high — every regression after `bootstrap-verify` will hit this until documented. **Mitigation**: Action Item 4 — document in `CONTRIBUTING.md`.

- **R4 — Docker-based slow tests are flake-prone on cold runners** (2.11, 2.14, 2.15 mitigated). Image build time, healthcheck timing, bind-mount permissions on macOS dev hosts. **Likelihood**: low after Story 2.15's M2/M14 fixes (build-base dep + 180s healthcheck timeout + SHA-tagged image cache). **Mitigation**: continue monitoring nightly CI flake rate; Action Item 9 (consolidate `skip_if_no_docker`) reduces the surface area for divergent flake behavior.

- **R5 — Stdlib `logging` vs structlog asymmetry** (2.16, 2.17 documented). `audited_secret` warnings go through `logging.getLogger(...)`; structlog warnings go through `redact_secrets`. Future stories may inadvertently log via the wrong channel and bypass either capture path. **Likelihood**: medium during Epic 3 (telegram-gateway will introduce its own log discipline). **Mitigation**: Story 3.1 (telegram-gateway bootstrap) should explicitly choose structlog and document the decision.

- **R6 — The `BaseHTTPMiddleware` + `request.state` collision** (2.13 Spec Amendment). Concurrent requests collapse `idempotency_key` to LAST-arriving header. Pre-existing; orthogonal to 2.13. **Likelihood**: high under any Epic 3 concurrency test. **Mitigation**: Action Item 11 — Epic 3 middleware story addresses.

Stories that quoted architecture.md line numbers in their Dev Notes shipped with fewer review findings than stories that summarized architecture from memory. 2.4 (file durability), 2.6 (snapshot HIGH-RISK callout), and 2.16 (Actor.kind canonical set discovered in 2.10's review) all cite specific architecture.md line numbers in their Dev Notes; their review findings were lower per-AC ratio than 2.7 (idempotency cache, no architecture.md line refs in Dev Notes — 4 CRITICAL) and 2.13 (idempotency wiring, sparse architecture refs — 3 CRITICAL). Correlation, not causation — but the practice of dropping architecture.md line numbers into Dev Notes is cheap and the observed correlation is striking. **Worth carrying into Epic 3 specs as a soft norm.**

Similarly worth flagging: the stories with the fewest review findings (2.5 — materializer, 2.9 — registry-api HTTP) are also the stories with the largest spec files (2.5: 476 lines; 2.9: 477 lines). Dense specs that pre-resolve ambiguities at spec-time produce code that survives review with less rework. The "spec files are growing in proportion to scope" pattern in the Recurring Patterns section is a feature of this cycle, not a bug.
