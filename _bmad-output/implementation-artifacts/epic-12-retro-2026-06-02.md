## Lessons learned

### L1 — "Disjoint domain models across epics" is a recurring coupling debt
**Pattern:** the *registry-level* budget override (`tier3.budget_override`, FR44, Epic 6.10/6.11) and the *worker-level* autonomous SIGTERM (`budget_supervisor`, FR66, Epic 12.1) implement the SAME concept ("budget") in two services with ZERO coupling. Stories 12.3 → 12.3a → 12.3c each re-discovered this gap; FR68's headline ("prevent enforcement within the grace window") was unachievable by the built flow and had to be bridged (12.3a) and is still only partially closed (12.3c).
**Conclusion:** when a second epic implements a domain concept a prior epic already modeled in a different service, the coupling is the real story — and it tends to span multiple follow-ups.
**Action AI-12.1:** at spec-authoring, when a story's FR references a concept already implemented elsewhere (grep the FR/event-type across services), FLAG the cross-service coupling explicitly and budget for a dedicated coupling story rather than assuming the headline AC is achievable in one.

### L2 — "Guard-until-wired" validator pattern for audit-integrity
**Pattern:** Story 12.2 added `_reject_unwired_budget_action` — a config validator that REJECTED `awaiting_approval` precisely because the FSM path didn't exist yet (emitting `post_trigger_transition="awaiting_approval"` while the FSM drove `TASK_FAILED` would make the audit event LIE). Story 12.3a implemented the path and removed the guard.
**Conclusion:** when a payload/config field can claim an outcome the code can't yet honor, a startup validator that fails-loud on the unwired value is the right bridge — it keeps the audit truthful and is removed (not bypassed) when the path lands. The load-bearing principle: `post_trigger_transition` MUST match the actual FSM outcome (override→`awaiting_approval` task-continues; terminate→hard-pinned `failed`).
**Action AI-12.2:** reuse the guard-until-wired pattern for any future audit field that precedes its FSM path.

### L3 — The critic lane catches HONESTY gaps the friendly lanes miss
**Discovery:** 12.3a's code + security lanes both APPROVED; the **critic** lane caught two MAJOR design/honesty findings: (1) the "continues under the *extended* budget" comment was misleading — it's a one-shot reprieve with no re-enforced ceiling; (2) the 5s window is impractical for ad-hoc human reaction (only pre-staged/automated overrides hit it). Neither was a code bug; both were truth-in-documentation gaps.
**Conclusion:** code-review + security-review verify "is it correct/safe"; only an adversarial/critic perspective reliably catches "does the code/doc claim something it doesn't do." For headline-feature stories, the 3rd (critic) lane earns its cost.
**Action AI-12.3:** keep the critic lane mandatory for any story whose FR is a user-facing "headline" capability (the gap between marketing-shape and implemented-shape is exactly where critic finds value).

### L4 — Delegate-then-diff-audit is non-negotiable for autonomous-enforcement code
**Pattern:** 12.4 + 12.3a were executor-built then orchestrator-diff-audited. The diff-audit independently verified the override fall-through, the fail-closed monotonic deadline, and the post_trigger truthfulness — and re-ran gates rather than trusting the executor's report (which it matched). 12.4's diff-audit also confirmed the precedence guards (bool/non-positive).
**Conclusion:** delegated work touching FR26 single-writer / autonomous enforcement / event-schema MUST be diff-audited by a separate pass + have its gates independently re-run. "Executor reported green" is necessary but not sufficient.
**Action AI-12.4:** (reinforces Epic-11 AI-1) — codebase-impact, not complexity estimate, triggers the diff-audit + multi-lane review.
