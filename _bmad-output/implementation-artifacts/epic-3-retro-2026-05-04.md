## Challenges and Growth Areas

### 1. Deferred Refactors Compounding

The cross-service IMP001 noqa cluster grew from 0 to 5+ entries across the epic. Story 3.10 identified the refactor (move payload models to `packages/events/`) but deferred it. Stories 3.11, 3.12, and 3.13 each added more entries. The fix was known and postponed four times.

### 2. Dev-Tooling Quirk Re-Discovery

The `uv sync --no-dev` quirk (strips `asgi-lifespan` from venv) was re-discovered in 10+ stories. Epic 2's retrospective recommended documenting it. Epic 3 did not document it. This is a process gap.

### 3. Review Energy Wasted on Repeated Findings

The `from_user=None` allowlist-middleware auth concern was raised and dismissed in 4 consecutive code reviews (3.16, 3.17, 3.18, 3.19). The architectural decision (allowlist middleware from Story 3.2 handles auth) was never documented in a shared location, causing reviewers to re-litigate the same question.

### 4. Documentation Staleness Accumulation

`docs/message-design.md` was written after Story 3.5 and never updated incrementally. By Story 3.20, 16 divergences had accumulated (wrong parse mode, wrong emojis, missing templates, incorrect budgets). The fix was a full rewrite rather than incremental updates.

### 5. Pre-Existing Test Failures as Noise

5 pre-existing test failures (crash-injection: 4, separability: 1 from Story 3.13) were carried through every subsequent story's regression verification, adding cognitive overhead and confusion to "all green" claims.

### 6. `approve_command.py` Double-@ Bug Never Backported

Story 3.4 shipped with a double-`@` bug in the operator handle rendering. Story 3.16 established the fix pattern. The fix was never backported to the original handler. Story 3.18's review flagged it as "out of scope." It persists in production.

### 7. Shared Helper API Gap

`extract_task_id_from_message` uses `split(None, 1)` which fails for commands with trailing free-text (reason, hint). Stories 3.17 and 3.18 both bypass it with `split(None, 2)` + inline regex. The workaround is duplicated with identical comments.

### 8. Spec-Implementation Drift

Story 3.19 had its AC spec retroactively updated to match implementation (AC-2 `@{handle}` addition). Specs should be source-of-truth before implementation begins.

## Key Takeaways

1. **Proactive review-pattern incorporation eliminates HIGH findings** — the clone-and-modify pipeline proved that baking prior review fixes into the next story's AC spec drives review yield to zero.

2. **The three-layer adversarial review is a force multiplier** — it catches issues the dev pass misses AND adds significant test coverage. The cost is substantial but justified by the zero-incident record.

3. **Undocumented decisions create review friction** — the `from_user=None` auth question consumed review energy across 4 stories. One ADR entry would have eliminated the waste.

4. **Deferred refactors compound faster than expected** — the cross-service import refactor was deferred from Story 3.10 through 3.13, adding noqa entries each time. The right time to refactor was after 3.10.

5. **Documentation staleness is a linear-cost problem that becomes exponential** — updating `docs/message-design.md` incrementally after each story would have been 20 small edits. Waiting to Story 3.20 required a full rewrite of 16 divergences.
