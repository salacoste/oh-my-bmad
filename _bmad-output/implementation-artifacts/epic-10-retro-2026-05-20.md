## What Went Well

### 1. Cadence stabilization (AI-1 proven)

Story 10.2's 3-pass review found 70 findings (28 + 24 + 18 — convergence curve). Stories 10.3-10.6 each converged at 1-pass with 13-20 findings. **The pattern is empirically proven:** thorough spec authoring + pre-resolved Decisions block + per-AC self-verification = 1-pass convergence for medium-complexity stories.

### 2. Decisions block discipline pre-empts mid-implementation drift

Every story pre-resolved 4-9 architectural decisions (D1-D9 per story) BEFORE `/bmad-dev-story` invocation. Executor delegations had near-zero "STOP and report" interruptions on decision-points. Story 10.6 (9 ACs, 6 decisions) executed cleanly without ambiguity escalation.

### 3. Cross-story lesson transfer compounds

Each story's review findings became inputs to subsequent stories:

- Story 10.3 P1-H1 (Counter labels race) → Story 10.4 pre-populated all ~42 enum children at `build_collectors`
- Story 10.4 P1-M2 (private prometheus API) → Story 10.5 used `parser.text_string_to_metric_families` exclusively
- Story 10.4 P1-H2 (ActorKind enum drift) → Story 10.5 AC6 fingerprints the startup assertion as regression gate
- Story 10.5 hotfix `d37f181` (date-rollover) → Story 10.6 has zero hardcoded dates

### 4. ADR-0005 as iterative architectural record

ADR-0005 grew via §Cardinality Discipline (Story 10.4 amendment) + §Deferred Metrics (Story 10.4) + §CI Regression Gate (Story 10.5). This iteration pattern works well — initial decision document, then amendments that record load-bearing invariants as they're discovered.

### 5. NFR-O8 latency budget validated empirically

p95 = 0.94 ms (Story 10.3 — benchmark fixture pre-populated to 50 timeseries) → 0.65 ms (Story 10.4 — actual ~50 production timeseries). **153× headroom** under the 100 ms budget proves the derived-projection architecture scales.

### 6. CI ratchet maintained zero regressions

5 of 5 review batches passed CI on first commit (one CI cancel + re-run was infrastructure-side, not code). Mypy `--strict` scope grew +20 source files with zero baseline regressions across the epic.

## Challenges

### 1. Recurring spec-vs-implementation label drift

- Story 10.3 P1-M1 — AC6 reason labels (`invalid_json|unknown_event_type|...`) drifted from impl (`json_decode|not_a_dict|...`)
- Story 10.4 P1-H2 — `ActorKind` 3-value enum in spec vs 5-value in `events.envelope.ActorKind`
- Story 10.6 A1 — AC3 self-verification ref'd UID 10003 + `user:` directive that was intentionally omitted

**Pattern:** spec values lag implementation reality when canonical source isn't cited inline.

### 2. Pre-existing tech-debt surfacing mid-epic

Story 10.5 CI cancelled twice on the same commit due to date-rollover flake — Story 10.2 legacy code hardcoded `2026-05-19.jsonl` in `test_day_rollover.py`, `test_exit_codes.py`, `test_restart_recovery.py`. Required Story 10.5 closure hotfix `d37f181` outside its scope. **Pattern:** tech debt with date/time hardcoding becomes a ticking time bomb.

### 3. Executor mid-step terminations (multiple instances)

- Story 10.2 pass-1 executor crashed at 87 tool uses (API auth error)
- Story 10.5 dev executor stalled mid-step ("Now update the ADR...")
- Story 10.6 spec authoring stalled mid-edit (resumed via SendMessage)

**Pattern:** long-running executor sessions hit budget/context limits. Need explicit checkpointing for batches >5 patches.

### 4. `subprocess.run` timeout gap (inherited tech debt)

Story 10.6 P1-H1 caught 8 `subprocess.run` calls without `timeout=` in the NEW S-4 separability test. The same gap exists in inherited S-1/S-2/S-3 separability tests (Stories 5.16, 5.17c, 2.15) but **was not fixed there** — Story 10.6 scope limited fix to S-4 only. Inherited gap persists.

### 5. `oh-my-bmad-base:local` prerequisite undocumented at CI level

Story 10.6 P1-H4 promoted Dockerfile thin-override pattern (`FROM oh-my-bmad-base:local`) to D7 Decision + AC2 self-verification step. But CI workflow `.github/workflows/*.yml` has no preflight `just build-base` step. Future fresh-CI runs would fail with `pull access denied` until that's added.

## Key Insights

### Insight 1 — Cadence convergence is a function of spec quality, not luck

Story 10.2's 3-pass was justified by genuine semantic complexity (tail-loop cursor restart-recovery, exactly-once vs at-most-once semantics, day-rollover edge cases). Stories 10.3-10.6 converged at 1-pass because spec Decisions blocks (D1-D9) eliminated ambiguity before implementation. **Action: continue Decisions-block discipline; resist temptation to "decide during dev".**

### Insight 2 — Cross-story pattern transfer compounds

Each story's lessons fed the next story's spec. Spec authoring should explicitly cite prior-story lessons (already practiced — Story 10.5 + 10.6 specs have "Lessons applied from Story X pass-Y" sections). **Action: formalize as spec template requirement.**

### Insight 3 — Reviewers need explicit instruction to differentiate "deferred-by-design" from "missed"

Story 10.4 D1 deferred idempotency/capability counters with `DEFERRED-FROM-FR62` docstring. Pass-1 reviewers correctly accepted this. **Action: spec Decisions block prevents reviewer false-positives.**

### Insight 4 — Cardinality discipline requires programmatic enforcement, not just policy

ADR-0005's "bounded enums" principle was reinforced by Story 10.5's regression test gate (`<= 52` baseline assertion + failure-injection test). Without the CI gate, future contributors could silently add unbounded labels. **Action: every architectural principle in an ADR should have a corresponding CI gate.**

### Insight 5 — Hotfix-as-debt is a real category

Story 10.5's `d37f181` migrated 3 Story 10.2 test files to date-dynamic paths. The fix was tactical (unblocked CI) but the underlying pattern (test-files hardcoding wall-clock dates) wasn't audited project-wide. **Action: project-wide audit needed for similar hardcoded-date patterns (see AI-4 below).**
