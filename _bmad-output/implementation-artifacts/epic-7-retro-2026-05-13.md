## What Went Well

### Architecture decomposition paid off

Most stories (7.4, 7.6, 7.7, 7.8) discovered the pipe was already built by prior epics. Work was wiring, materializer updates, and verification — not greenfield construction. The event-materializer-API-surface layering continues to decompose cleanly.

### Code reviews caught real bugs

33 findings across 6 reviewed stories, including:
- CRITICAL: `line_count` exceeding Pydantic constraint would have caused 500s in production (7.3)
- Race conditions in kill-restart integration tests caught across multiple review rounds (7.9, 7.10)
- Resource lifecycle issues (Anthropic client leak, 7.3)

### First external API dependency introduced cleanly

Story 7.3 (LLM digest adapter) integrated Anthropic with graceful degradation — falls back to raw-event formatting on API failure. This is the template for future external dependencies.

### Kill-restart-dedupe pattern is battle-tested

Journey 3 (7.9) and Journey 6 (7.10) prove the stub + dedupe + polling pattern works in CI. Two independent journey tests with different failure modes (restart recovery vs stale blocker) validate the platform end-to-end.

### Breakthrough: simpler than expected

Story 7.7 (worktree lock) expected complex persistence work. The file lock was already held — the gap was purely in materialized state visibility. Story collapsed to a simple handler update.

## Challenges

### Review finding volume

33 findings across 6 reviewed stories (~5.5 per review). Patterns:
1. **Boundary condition violations** — Pydantic constraints not checked in handler logic (7.3, 7.5, 7.7)
2. **Race conditions in test infrastructure** — kill-window timing, missing polling loops (7.9, 7.10)
3. **Resource lifecycle** — client cleanup, exception handling scope (7.3)
4. **Private attribute access** — reaching into internals instead of using public API (7.8)

### Integration test harness duplication (systemic)

Deferred across Epic 6 AND Epic 7 retros. Stories 7.9 and 7.10 copy helper functions from prior tests. Short-term incentive (faster to copy) works against long-term DRY principle. This is a systemic issue, not a discipline issue.

### Async materializer timing

Stories 7.9 and 7.10 required polling loops for materialized state because the materializer processes events asynchronously. Initial implementations assumed synchronous materialization. Fixed in review but the pattern kept recurring.
