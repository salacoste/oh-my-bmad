## Key Insights

### 1. Deferred-work tracker is working as intended

The tracker accumulated items across 12 stories (D1-D7 from 3.11/3.12/3.13, D1 from 3.6, D1-D3 from 7.7, plus individual defers). Epic 7.5 successfully resolved 8 of those items and added 18 new ones — a net increase of 10. This is expected: code review surfaces real issues that would otherwise silently compound. The tracker prevents loss.

### 2. The tech-debt sweep pattern (Epic 3.5 → Epic 7.5) is validated

Both sweep epics followed the same playbook: batch HIGH/MEDIUM items from retros, resolve them before propagation, produce new deferred items at a lower average severity. The Epic 7.5 deferred items are overwhelmingly LOW priority — the HIGH and MEDIUM items that triggered the sweep are resolved.

### 3. Pydantic's Rust regex engine is a real constraint

Story 7.5.8 discovered that Pydantic's `pattern=` field uses a Rust regex engine that doesn't support lookahead/lookbehind. The workaround is `@field_validator` with programmatic checks. This affects all future pattern validation design.

### 4. Test cascade from model validation changes

Adding `pattern=` to `task_id` broke 81 tests across 7 test files. The fix required understanding which tests genuinely needed valid IDs vs. which needed `model_construct()` to bypass validation for defense-in-depth testing. This pattern will recur whenever model validation is tightened.

### 5. Integration test harness: third retro's the charm

The integration test harness duplication was flagged in Epic 5, Epic 6, and Epic 7 retrospectives before finally being resolved in 7.5.7. The ADR-0002 hybrid approach (extract compose helpers, keep per-file harness classes) was the pragmatic middle ground that stuck.

## Action Items

1. **Continue deferred-work tracker discipline** — The tracker has 50+ items accumulated across all retros. Periodically triage for items that have become blocking or can be batch-resolved.

2. **Pattern: `@field_validator` over `pattern=` for complex validation** — When Pydantic validation needs sequence rules (no `..`, no `//`, etc.), use `@field_validator` instead of trying to express it in regex. Document this in project conventions.

3. **Pattern: `model_construct()` for defense-in-depth tests** — When tests need invalid data to test downstream renderer/sink behavior, use `model_construct()` to bypass Pydantic validation. Document this in testing-guide.md.

4. **Periodic regression baseline** — The 20 pre-existing test failures (registry-api, registry-state, worker-wrapper) have been stable across the entire Epic 7.5 sweep. Investigate whether they represent real issues or test infrastructure gaps.
