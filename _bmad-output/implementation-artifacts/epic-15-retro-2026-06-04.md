# Epic 15 Retrospective: σ git MCP server — the recipe-establishing fleet server (Phase 3 Epic 2 of 6)

## Epic Summary

Epic 15 shipped `git-mcp` — the **first real Phase-3 fleet server** and the reference
implementation of the MCP-server-authoring recipe (ADR-0010). It exposes bounded git operations
over a sandboxed worktree: `status`/`diff`/`log`/`branch` (Tier-1 read), `add`/`commit` (Tier-2
mutate), `push`/`rebase` (Tier-3 approval-gated), each emitting `git.*` spine events. 7 stories,
merged across PRs #38–#42 (15.1/15.2/15.2a as a trio in #38; 15.3 #39; 15.4 #40; 15.5 #41; 15.6
#42), all CI-green. ADR-0010 accepted; the P3-I1 untiered-tool AST gate (`check_tier_declarations.py`)
built as a fleet-wide deliverable (15.2a).

The epic's defining characteristic: it is where the recipe was **discovered by building**, and
where the worktree-as-untrusted-sandbox threat model was driven home by **four P0 security defects**
that the executor's first passes shipped open and the security-reviewer caught.

## Story-by-Story Highlights

- **15.1 + 15.2 + 15.2a (PR #38, trio):** ATDD red-phase + scaffold + the P3-I1 AST gate landed
  together — the ATDD contracts import scaffold symbols (empty `TIER_MAP`, `build_server`) and must
  fail at *runtime*, not collection. 15.2a's gate had 2 P1 false-negatives (dead-code / nested-helper
  `TIER_MAP` bypass) hardened to count only direct args to `check_tier`.
- **15.3 (PR #39):** read tools. **P0 #1: repo-local `.git/config` RCE** — `core.fsmonitor`/
  `core.hooksPath` execute arbitrary commands on a mere `git status`, and hermetic
  `GIT_CONFIG_*=/dev/null` does NOT stop it (git reads repo-local config on every op). Fixed with
  per-invocation `-c` shields (`_GIT_HARDENING`).
- **15.4 (PR #40):** mutating tools + Tier-3 push/rebase + `git.*` events. **P0 #2/#3/#4:**
  `filter.<name>.clean`/`merge.<name>.driver` RCE (attacker-NAMED drivers via `.gitattributes` —
  `-c` can't fix them; needs a pre-op config-scrub) + `url.<x>.insteadOf` SSRF/exfil (local→network
  rewrite; closed by `protocol.allow=never`).
- **15.5 (PR #41):** child-env allowlist (`GIT_MCP_*`, byte-identical orch↔worker) + conditional
  spawn (off-by-default) + S-5 separability.
- **15.6 (PR #42):** supply-chain confirmation — git-mcp adds zero new third-party deps; ADR-0010
  finalized. Also backfilled the stale sprint-status (15.1–15.5 were merged but still `backlog`).

## Key Lessons (3 — carried forward to Epics 16–19)

### L1: The worktree is the untrusted sandbox — repo-local config is part of the threat surface
Env-hermeticity (`GIT_CONFIG_GLOBAL/SYSTEM=/dev/null` + drop `HOME`) is **necessary but not
sufficient**: git reads the attacker-writable `.git/config` on every op. There are TWO exec-vector
classes needing TWO defenses — fixed-key vectors (`-c` overrides) and attacker-NAMED driver vectors
(a pre-op `git config --local --list` scrub, since `-c <key>=` can't target an attacker-chosen name).
Both were caught by the security-reviewer AFTER the executor's first pass shipped them open. (Saved
to memory: `git-repo-local-config-rce`.)

### L2: Lock every security fix with a prove-live→assert-shielded regression test
Each P0 fix shipped with a regression test that (a) proves the vector executes live *unshielded*,
then (b) asserts the shielded path blocks it. This is the only way to know the fix actually fixes —
and it catches a future refactor that silently removes a shield. Every Epic 16–19 destructive tool
inherited this discipline.

### L3: Independent security review is not optional on a tool that shells out / touches secrets
The executor's first passes were *functionally correct* and *gate-green* but security-open. Default
code review and the AST gates did not catch the RCE/SSRF vectors — only an adversarial security lens
did. The cost of the review was trivial against shipping an RCE. This became the per-server gate for
the fleet.
