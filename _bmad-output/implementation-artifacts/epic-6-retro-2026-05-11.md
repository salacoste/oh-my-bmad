## Successes

1. **Two-layer enforcement architecture (6.1, 6.2)** — `check_tier()` (synchronous actor-kind gate) + `check_tier_with_approval()` (async approval lookup) compose cleanly across MCP and HTTP surfaces.

2. **Materializer as reflector, not driver (6.5, 6.6)** — Materializer handlers only update timestamps and `last_event_id`, never drive state transitions (except `stop` → terminal). Prevented race conditions with worker lifecycle FSM.

3. **Gate check placement before idempotency cache (6.10, 6.11)** — Blocked approvals don't consume idempotency slots. License and budget gates run after state validation but before the cache.

4. **Dual-layer defense for license scanning (6.8 + 6.9 + 6.10)** — Local precommit hook blocks offline; worker event emission + approval gate blocks online. Operator always retains override authority.

5. **Progressive integration test maturation (6.12 → 6.13 → 6.14)** — Three validation-only stories built increasingly sophisticated harnesses culminating in dual-actor tier enforcement tests.

6. **Per-function RNG pattern established (6.12 review)** — Replaced shared module-level `_RNG` with `rng = Random(42)` inside each function. Prevents Hypothesis reproducibility issues and state leakage.

---

## Challenges

1. **Tier-3 enforcement gap at middleware layer (6.14)** — `TierEnforcementMiddleware` never passes `has_approval=True` to `check_tier()`, making Tier-3 routes always fail regardless of actor kind. Actual Tier-3 gate happens at MCP handler level. Discovered during implementation.

2. **Integration test harness duplication (6.12, 6.13, 6.14)** — Nearly identical `_Harness` classes across 3 test files. Scope constraint ("DO NOT modify conftest.py") prevented consolidation.

3. **Materializer-not-running confusion (6.12, 6.13, 6.14)** — Every integration test story independently rediscovered that gate checks query SQL while emission verification reads JSONL.

4. **FrozenClock + deterministic RNG = UUID collision (6.13)** — Two calls with frozen clock + internal `Random(42)` produced identical event IDs. Fix: pass `rng` from caller.

5. **Route prefix matching edge case (6.14)** — `_resolve_tier`'s `startswith(prefix + "/")` fails with trailing-slash entries producing double-slash paths.

6. **Stories 6-1 through 6-4 incomplete Dev Agent Records** — First four stories lack model, debug logs, and completion notes. Tracking rigor improved from 6-5 onward.

---

## Key Insights

1. **Tier-3 has two distinct failure paths.** Worker → actor-kind gate. Operator → approval gate. Different `detail` messages in 403 response. Both must be tested for NFR-S6.

2. **Gate assertions must match the right data store.** `_check_license_gate` and `_check_budget_gate` query SQL Event table. Emission verification reads JSONL. Confusing these causes false passes.

3. **Integration test harness pattern is mature and should be shared.** In-process ASGI + ASGITransport + LifespanManager + writable engine + FrozenClock + owned event loop — used consistently across 3+ test files. Extract to conftest.

4. **Code review catches real AC violations.** Story 6.14 review found missing side-effect assertions (AC #2) and misleading positive control (AC #3 deviation). Three-layer review continues to deliver value.

5. **Per-function RNG is the established pattern.** Every test function creates its own `Random(42)`. No shared module-level RNG.
